# ADR 0004 — yfbzb SafeLine 403：按站点自报末页位置区分边界与拦截

- **日期**: 2026-10-28
- **状态**: 已采纳
- **上下文**: yfbzb 的页尾 403 是 SafeLine（雷池 WAF）拦截页；临时封禁返回同一张页，响应体指纹（`/.safeline/`）无法区分两者。原实现把所有 403 当数据边界，临时封禁会被静默当成「已到底」：日志无告警、断点被删、后续数据永久漏掉。

## 背景

2026-10-27 实测（`.scratch/yfbzb-live-probe/FINDINGS.md`）：

1. yfbzb 自报 100 页（「共 3000 条」÷ pageSize 30）；抽测第 1、50、75、88、94、97、99 页均为 200 正常列表页，第 99 页二分复测仍为 200；第 100 页为 403 SafeLine 拦截页，说明是页码上限而非速率触发。
2. 第 100 页与临时封禁返回同一张 15671 B 拦截页（引用 `/.safeline/static/favicon.png`），单看响应体不可分。
3. 原 `defaultIsBoundary` 把所有 403 当边界；临时封禁因此会被当成正常收尾。
4. 规格建议（FINDINGS §3.1）是「命中指纹就不视为边界（换点或告警）」，但 yfbzb 直连无代理，且末页 403 是确定性页码上限，若一律按失败页会让断点永远卡在末页。

## 决策

1. 站点新增可选 `blockType(error)` 钩子：`yfbzb` 对含 `/.safeline/` 的 403 返回 `'safeline'`；`isBoundary` 同时排除该指纹。
2. `crawlPage` 对命中 `blockType` 的 403 快败为失败页（`shieldType`，不重试，同一出口重试只会再吃拦截页）。
3. `crawl()` 在逐页判定时，仅当 **`shieldType === 'safeline'` 且该页 >= 已知站点末页** 时，才把失败页改写为数据边界（`boundary_blocked_last_page`，`warn`）。已知末页优先取站点自报总页数；配置 `TOTAL_PAGES` 小于真实页数或该页位于中间页时一律按失败页，连续 2 页由 breaker 熔断并保留断点。自报总页数写入断点（`realTotalPages`），恢复轮优先使用；旧断点没有该字段时退化为配置上限，避免恢复轮从末页起跑、无成功页可观测而永久卡住。
4. 自报总页数的合并从批末前移到逐页判定之前，保证同一批里靠前页的观测先于末页判定生效。

## 取舍

- 位置判别无法区分「真实页尾」与「恰好打在末页的临时封禁」。选择接受：yfbzb 直连无换点能力，位置是唯一可用信号；错误方向被限制在「把一次末页封禁当收尾」，而反向错误（把页尾当失败）会让断点每天卡在末页、永远抓不到新数据。
- 不用配置上限（`effectiveTotalPages`）作为判据：配置小于真实页数时，上限页是真实数据页，被拦必须按失败保留断点。
- 未观测到自报总页数时退化为配置上限：恢复轮可能只从末页起跑、没有成功页可重新观测，若坚持「无证据就按失败」会让断点永停末页、每轮零新增。代价是临时封禁恰好打在配置末页时可能被当边界；这一风险被限制在「旧断点 / 上轮从未成功观测」的恢复轮。

## 影响

- `sites/yfbzb.js` 新增 `isBoundary`/`blockType`；`crawler.js` 新增末页位置判别与 `boundary_blocked_last_page` 事件。
- `breaker.js` 的 shield 熔断计数同时覆盖 acw 与 safeline；`trip()` 带回 `lastShieldType` 供日志区分，末页规则本身只对 safeline 生效。
- 测试：`test/safeline403.test.js` 覆盖末页边界、中间页熔断、同批观测收窄、配置上限小于真实页数；`test/aliyun_waf.test.js` 增加 acw 末页不得被该规则吞掉的回归。
